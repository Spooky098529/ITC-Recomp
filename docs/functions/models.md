# Known functions: models, textures and shaders

The graphics library's model loading and recording: a part file (`00 15 00 00`) parsed into a model (its head copied, its vertex data into physical memory, its shaders made), its node file's skeleton, and each shape's draws recorded with their shaders, constants, render states and textures (`Model::RecordShape`; `Model::RecordMaterials` for car parts, with the shared material shaders and the vinyl sheet); the XPR2 texture bundles (`XPR::`); and the boot's shader pairs (`Shaders::LoadAll`). How the recorded commands are replayed is in `../gpu-functions.md`.

The rows were drafted on 2026-10-23 from SBX-Recomp's `docs/game_data.md` (the Japanese release's recomp; `../referencing-sbx-recomp.md`), each fact checked against our `generated/` code: offsets and asset ids are our build's, which differ from SBX-Recomp's in places. "Name from SBX-Recomp" marks the names taken from it; the others are ours. The data layouts are in `../known-data.md`.

The model class's constructor and destructor (`Model::Model`, `Model::~Model`), its texture provider (a `std::vector` of texture pointers, with the vector's helpers), the XPR's destructor and release, and the frees they put off to the pass's start (`Memory::FreeLater`, the pending frees' `std::list`) were added on 2026-10-25 by the B7 loop's mapping agent (`../loops/b7-loop.md`), read in our `generated/` code. Their blocker is the memory blocks' lock: `Memory::FreeLater` and `FreePhysicalLater` take `ScopedLock` over the critical section `0x8296BD38` (`video-output.md`, which stays recompiled as the core's sync, the user's call of 2026-10-24), so `XPR::Release`, `Model::Release` and both destructors wait on it; the constructor waits on `TextureProvider::TextureProvider`'s vector helpers only, and ready below it are `XPR::XPR`, `TextureProvider::Allocate`, `UninitializedCopy`, `memmove_s` (`c-runtime.md`) and the pending frees' insert. The user's call (2026-10-25): the lock is ported too, a host mutex in place of the critical section for every user of it (`models::MemoryBlocksMutex` in `src/models/memory_blocks.h`; the recompiled users take it through `ScopedLock`'s adapters, `video-output.md`), so `Memory::FreeLater`, `FreePhysicalLater` and the pending frees are native (`--native_models`, harness `models`). The migration (2026-10-25) then made the rest of the class native under the same flag: `XPR::XPR`, `Release` and `~XPR` (`src/models/xpr.cpp`), the texture provider and its vector's helpers (`src/models/texture_provider.cpp`; `memmove_s` in `c-runtime.md`) and `Model::Model`, `Release` and `~Model` (`src/models/model.cpp`); the adapters stay where recompiled callers remain (the car code, the course scenery, `sub_82594718`, `sub_825911C8`, `sub_82591238`).

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
