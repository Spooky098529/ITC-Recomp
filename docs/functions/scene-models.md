# Known functions: the scene models

The scene models: the cars as the scene holds them, in the second set
of the scene's object pools (`[0x826C2E44]`, the scene; `ScenePools::ClaimB`,
`GetB` in `vehicle-accessors.md`). A scene model (pool 7) is built from
a 4,244-byte record (the kind, a 3,696-byte car record and the records of
its parts) and claims its parts in the other pools of the same set: the
car model (pool 0), the parts (1), the cockpit (2), the interior (3),
pool 4, the wheels (5) and, for traffic, the traffic body (6). Each of
those claims its loading object in the first set (`[0x826C2E40]`,
`ScenePools::SetUp` in `vehicle-accessors.md`), whose loaders are in
`car-models.md` or here (the parts' sets a and b, pool 4's and the traffic
body's). This file holds the set-up side: the pool 7 set-up and its
build (now or deferred to the per-model update), the set-up dispatch over
the second set's eight pools, the links between the parts, the records'
defaults and copies, the first set's loaders not in `car-models.md`, the
record re-applied to a model already built, and the update's accessory
placement (never ran in play). Not in it (leads in `../loops/leads.md`):
the load poll that finishes the parts (`sub_820DA318` and the Wrapped
finishers in `functions.md`), the release (`sub_820C5C88`, Wrapped in
`functions.md`, and its eight cases), the scene models' owners in the race
and front-end code (`sub_8215C0D8`, `sub_8217F880`, `sub_8217FCB0`,
`sub_8217FC60`, `sub_82179998`), the scene's own update and teardown
(`sub_820C9608`) and the per-slot sound loads' readers. Shared, with their
rows elsewhere: `sub_820C5A60` (the update's walk over pool 7,
`vehicle-accessors.md`), `ScenePools::SetUp` (`sub_820C4338`,
`vehicle-accessors.md`), the wheels' set-up (`sub_820E70C0`), the load
slots (`sub_820D0860`, `sub_820D07C8`, `sub_820D0758`),
`CarModel::LoadExterior`, `CarInterior::LoadSetCBody`,
`CarInterior::Load`, `CarModel::ReloadDecals`, the wheels' loader
(`sub_820D9110`) and `Texture::Create` (`sub_820ECF08`) in
`car-models.md`; `Model::HasPoint` and `Model::PointPosition` in
`race-overlays.md`; `Archive::Load` (`sub_8209DE48`) and the asset's size
(`sub_820A0678`) in `files-and-saves.md`; `Model::Load` (`sub_82596920`)
in `models.md`. The scene model's fields, its record and the globals are
in `../known-data.md`. Mapped by the B7 loop's mapping agent, 2026-10-25
(from the lead `sub_820DA180`, `sub_820D97B8`, `sub_820D9870`).

The scene's +4 picks two ways of building: 0 probably the front end
(the garage: parts re-applied in place), 1 probably a race (parts
rebuilt; the cockpit and the per-slot sound loads only then). A scene
model's kind (+32, the record's +0): 1 and 2 cars (only kind 2 gets the
cockpit, probably the player's car), 3 traffic (the traffic body and the
wheels only).

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
