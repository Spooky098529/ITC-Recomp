# Known functions: collision

The collision world's narrow phase and its shapes: what happens to a
pair of collision objects once the world (`functions/car-physics.md`)
has decided to look at it. Each collision object carries, at its +32, a
shape record (`CollisionShape`: the shape it was made from, two placed
copies of it, the swept bounds of both and the motion between them),
placed by its rigid body's matrix each tick (`CollisionShape::Place`,
`sub_820BB758`, from `CollisionWorld::Update`) and moved when a response
pushes it (`CollisionShape::Translate`, `sub_820BACD0`). The only shape
seen in play is a box (`BoxShape`, 496 bytes, vtable `0x82002B30`, made
from the car data's two corners by the vehicle's physics set-up: the
vehicle's +344 object), over a base class (`Shape`, vtable
`0x82002AA8`); the vtable-only methods at `820B9C40`-`820BAA50` are the
box's (placed, moved, its corners, faces and edges). A pair is solved
(`CollisionPair::Solve`, `sub_820BBE30`, from
`CollisionWorld::SolvePairs`) with a query record on the stack: first a
cheap test that a face of one box separates the other at both the
previous and current placements (cached in the pair's +24), then up to
10 impacts (a corner of one box crossing a face of the other between
the two placements) and up to 3 push-outs (corners, then edges, along
the direction between the boxes), each answered by
`CollisionPair::Respond` (`sub_820BB868`): the objects moved apart by
their mass shares (`CollisionObject::Translate`), an impulse from
`RigidBody::ContactImpulseWith`, and a contact added to each. The time
a pair is next looked at comes from its bounding spheres and the
bodies' speeds (`CollisionPair::NextCheckTime`, `sub_820BBB20`). The
query picks its tests from two tables by the shapes' types (3 kinds,
`0x82600EB4` and `0x82600E90`); only the box-box entries ran.

Shared with other files, which keep their rows: `CollisionShape::Init`
(`sub_820BAA78`, the record's constructor), the collision objects,
pairs and the world (`CollisionWorld::UnlinkPair` `sub_820BBC40` and
`MovePair` `sub_820BBD30` sit in this range), `CollisionObject::Init`,
`ResetTransform`, `Translate`, `AccumulateForce`, `AddContact`,
`RigidBody::ContactImpulseWith` and the vehicle's physics set-up
(`car-physics.md`); the rigid body accessors (`RigidBody::Mass`,
`IsFixed`, `Velocity`, `sub_820B6890`, `sub_820B68A0`) and the vector
library (`vehicle-accessors.md`); the matrix math (`matrix-math.md`);
`memcpy` (`c-runtime.md`); operator new and delete (`heap.md`). Two
one-instruction accessors named for the rigid body are used on the box
too: `sub_820B6890` (r3 + 144, its row in `vehicle-accessors.md`; the
box's inverse half extents here) and `sub_82379328` (r3 + 128, `RigidBody::Torque`, its row in
`vehicle-accessors.md`; the box's half extents here). The track's
queries that call the shapes (`820FC188` to `820FF1B0`) are leads too.

Floats named by address are in `.rdata`: `0x82000A30` is 1.0,
`0x82000A34` 0.0, `0x82001BE4` 0.5, `0x82001BE0` -1.0, `0x820021E8`
2.0 (as in `car-physics.md`); `0x8200222C` is a small epsilon, probably
(a squared length's floor and the depth's bias), `0x82002B90` the
impact time limit (probably 1.0) and `0x82002B94`, `0x82002B98` the
edge test's limits (not read from guest memory). The fields of the
shape record, the box and the query are in `docs/known-data.md`.

Things a native version has to keep (the game's own behavior):
`BoxShape::FaceDirection` (`sub_820B9F00`) returns a static vector at
`0x826C2DE0`; `CollisionShape::Previous` and `Current` call the
template's type method and drop its answer; `CollisionShape::Place`
swaps the two placed copies before placing, and for a box with the
record's +112 set it places from a copy of the template with its
bottom lowered on the stack; the tests compare with `fcmpu` branches
as written (NaNs take the "not less" and "not greater" sides); the
query and its four 336-byte relative-placement blocks are on the
stack (1,632-byte frame); `BoxBox::PushOutCorners` reaches
`sub_820BE0D8` and `sub_820BC8A8` only with a corner inside the other
box, which didn't happen in play.

Native (B7 loop, 2026-10-22, `--native_collision`, on by default):
`src/collision/` written as the car physics' plain C++ is
(`car-physics.md`: the originals' loads, stores and float steps in their
order, temporaries in their own stack frames, built with
`-ffp-model=strict -ffp-contract=off`), the vector library's plain C++
called directly; adapters in `src/hooks/collision.cpp`, harness
`collision` (boxes, a shape record, a contact and a query 128 KB down the
guest stack). The box's vtable `0x82002B30`, read in play: slot 0
`sub_820BB140`, 1 `sub_820BB410`, 2 `sub_820BA888`, 3 `sub_820BB450`, 4
`sub_8244A528` (its type: `li r3,2`), 5 `sub_820BB218`, 6
`sub_820BB270`, 7 `sub_820B9FF8`, 8 `sub_820BA1D0`, 9 `sub_820B9C40`, 10
`sub_820BA2F0`, 11 to 18 `sub_820B9EC8` to `sub_820B9FB0` (as the rows
say), 19 `sub_820BAA48` (returns 4), 20 `sub_820BA668`, 21
`sub_820BA678`, 22 `sub_820BAA50`, 23 `sub_825C8390`. The native code
makes the shapes' virtual calls itself only for a box (the vtable word
checked), and leaves the type call out (a leaf); any other shape runs the
original. The harness's "(expected to differ)" groups: NaNs and
infinities anywhere (where two NaNs meet, which comes out depends on the
operand order the compiler gave the operation, in the translated code as
in ours; the game's boxes hold no NaNs), and for the motion's row (+96,
`UpdateMotion`, `Place`, `Translate`) one NaN in the current center that
meets its own negation in `Vec3::Sum`. Frames dumped 10 s into an attract
race show the AI cars in the same places with `--native_collision` on and
off.

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
