# Known functions: the race event

The race event (`RaceEvent::`, 160 bytes at `[0x826C6078]`;
`82140340`-`82144E58` with the condition tests from `8213FE00`): the
opponents a career race offers, made by `Career::SetUpEvent`
(`career.md`) for a mode and a location. The 400 items (the data tables'
3,008-byte entries, `DataTables::Item` in `data-tables.md`; the opponents)
whose mode mask and level fit are sorted by their unlock state into
pools by location (ten, the item's +36), trimmed to each location's cap
(with `rand`), and copied into ten groups of open and locked entries;
locations 0 to 3 also get the event's list (+156, 12-byte entries: the
item id, a start position, a flag), which the race's set-up reads
(`RaceEvent::Current`, `FirstOwned`, `CurrentFirstOwned`, `Count` in
`race-setup.md`) and the race world places on the road
(`RaceEvent::PlaceStarts` and its parts, `race-world.md`). Later the
career refreshes it (`Career::EventQuery`, `Career::EventLocation`),
the race states place opponents unlocked during a race and a hidden
section rival (kind 65: the player's car over given slices of sections
13, 14, 4 and 5, flagged by `AiPath::NoteFixedSections` in
`ai-drivers.md`), and the front end reads its groups. An item's unlock
block (+40) holds two 20-byte conditions, all or any; each condition is
one of 68 kinds of test over the save data, the garage's selected car
and the event (`EventCondition::Met`, a jump table): "the arguments"
below are a condition's four words +4 to +16, those below 0 skipped, and
"the car" is the garage's selected car (save +6120, `race-setup.md`'s
garage walk) when `Params::Exists`, else the race data's first racer
record. Fields are in `../known-data.md` (`0x826C6078`, race event
group, event pools, event condition, item). Names are ours and mostly
guesses. Read 2026-10-30 by the B7 loop's mapping agent (all of it
in full; only kinds 21 and 31 of the tests ran in play).

Shared, with their rows where they are: `RaceEvent::FirstOwned`,
`CurrentFirstOwned`, `Current` and `Count`, `Car::Init` (`race-setup.md`);
`RaceEvent::PlaceStarts`, `PlaceStartsCurrent`, `PlaceGroup`,
`PlaceGroupFixed`, `PlaceGroupTwoRows`, `PlaceGroupSplit`, `PlaceEntry`,
`Entry` (`sub_82144798`, `sub_82144874`, `sub_821443B0`,
`sub_82143A40`, `sub_82143B78`, `sub_82143920`, `sub_82143150`,
`sub_82143508`, `sub_82143608`, `sub_82144A38`) and
`SaveData::FirstUnsetFlag` (`race-world.md`); `SaveData::Of` and
`sub_820C4550` (`vehicle-accessors.md`); `DataTables::Item` and
`IsLoading` (`data-tables.md`); `TrackRoute::Normalize`, `ToMainRoad`
(`track-route.md`); `AiPath::BranchMasksFor`, `RaceTime::FromTicks`
(`ai-drivers.md`); `Params::Exists`, `GetCarSpec`, `Car::Refresh`
(`car-specs.md`); `PowerCurve::ShiftPeak` (`vehicle.md`);
`DayBlock::BestStreak` (`career.md`); `rand` (`race-overlays.md`);
`VirtualAlloc`, `VirtualFree`, the `operator new`s and `delete`s
(`heap.md`); `memset`, `memcpy` (`c-runtime.md`); `sub_82106540`
(`audio.md`). Callers outside: `Career::SetUpEvent`, `EventQuery`,
`EventLocation` (`career.md`), `RaceStates::NextMessage`, `LinkTick`,
`NewStage` (`race-states.md`), `sub_8225AB30` (`RaceEvent::Destroy`'s,
front end, not mapped) and the front-end menus (`82227430`-`8222EAD0`,
their lead in `../loops/leads.md`).

What a native port meets (read 2026-10-30): no kernel imports, kernel
objects or locks; the allocations go through the game's `VirtualAlloc`
and `operator new` wrappers, already ours (`heap.md`). Every callee
outside the file that runs in play is ours; the ready groups wait only on
each other. `EventCondition::Met` branches through a jump table in
`.rdata` (bytes at `0x82008D98`, 68 kinds); the recompiler split its
case 1 off (`sub_82142868`), which a native port does inside its caller
(Merged). Of its 61 tests only kinds 21 and 31 (with
`EventCondition::CategoryMask`) were seen in play: the rest are "Not seen
in play" (the career's front end and saves weren't driven far), so a
port of `EventCondition::Met` takes them unseen or keeps their
recompiled path. Tables read (values not worked out): `0x82008D74`
(halfwords, a location's group), `0x82008D88` (words by mode),
`0x82008DF4` (the modes' item masks), `0x82008E00` (the caps of
locations 0 to 3), `0x82008E08` (bytes, the stage each location needs),
`0x82001FB0`, `0x82000A30`, `0x82008E34`, `0x82008E38` (floats).
`RaceEvent::Init` leaves the pools' block (6,080 bytes) and its stack
words as the original does; `EventPools::Trim` calls `rand` as many
times as the original (B7 changes no behavior). Nothing here needs a
call the user hasn't made.

Made native 2026-10-30 by the B7 loop (`--native_race_event`, code in
`itc_recomp/src/race_event/`, adapters in `src/hooks/race_event.cpp`,
harness `race_event`): all of it but `EventCondition::Power` (kind 40, never
seen in play, its power curve not ours yet), which native
`EventCondition::Met` runs through the adapter's guest call. That test reads
stack words below it that it never writes, so the guest call runs at the
original's depth: each native level adds its original frame
(`race_event::Guest::Down`; frames: Met 96, State 96, All and Any 128,
StateKind2 and 5 112, Unlock::State 96, Items::Available 96, AddItem 128,
Init 208, Make 128, Refresh 128, PromoteUnlocked 144, UpdateLocation 96,
SectionRival 144, PlaceUnlocked 192; the tails none). Only the entry points
the recompiled code calls keep adapters (Make, Destroy, PlaceUnlockedCurrent,
SectionRivalCurrent, Items::Available, GroupItem); RefreshCurrent and
UpdateLocation are reached from `--native_career`'s `Career::EventQuery` and
`EventLocation`. The harness leaves r3 out for the functions returning
nothing (their r3 is their last callee's; no caller reads it), and keeps
`EventCondition::Power` to its own cases (with random car specs, its car
copy follows wild pointers) and an event and the car specs set where a test
reads them unchecked (kind 65's event, kind 40's specs: null ones fault, the
original too).

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
