# Known functions: the other in-race screens

The **other in-race screens**: the pause menu, the confirm dialog, the
career's results, the menu after the race and the makers of four
screens never seen in play, made by the in-race screens' holder's
maker and destroyed by its teardown (`RaceScreens::Create`
`sub_82211F40`, `RaceScreens::Destroy` `sub_82211D18`,
`race-hud-object.md`; the holder's +1012 to +1036 copy their globals,
`RaceScreens::Init`), and run by the race HUD machine's handlers
(`race-hud-machine.md`: the pause menu opened by `OpenPause`,
`OpenRacePause` and the rest, updated by `PauseUpdate`, drawn by
`PauseDraw` through `sub_82211D08`; the results and the menu after the
race by `OnRaceEnd`, `ResultsUpdate`, `ResultsDraw`, `AfterRaceUpdate`,
`AfterRaceDraw`). Names are ours. Each screen is a set of small
allocations (`VirtualAlloc`, `sub_82295398`, 4 KB pages, read-write; at
global addresses, `../known-data.md`), most of them: a 4-byte object
holding the screen's UI movie (found by id in the movie table
`0x826C5CCC`, `UiMovies::Find`), a data block, a **page object**
(`ScreenPages::`, 28 bytes: +0 the page, -1 while a transition runs; +4
the page a transition leads to; +8 the previous page; +12 the running
transition, -1 none; +16 a queued transition; +20; +24 the running
transition's step word, passed to it as r3) and a **menu list**
(`MenuList::`, 72 bytes, the front end's shared list: +0 the item count,
+4 the first item shown (the scroll), +8 the scroll before, +12 the
items shown, +16 the selection relative to the scroll, +20 the
selection before, +24 the last move (1 down, -1 up, 0 none), +28 left
or right (-1, 1), +32 set when the move wrapped or skipped, +36 to +48
the action ids for down, up, left and right, +52 the accept action, +56
the back action, +60 the player, +64 wraps, +68 a block of a word an
item, 0 for a disabled item; `MenuList::Init` in `save-data.md`). A
screen's update runs its page's handler (a table on the stack) when no
transition runs, and the handler's input switches pages
(`ScreenPages::Go`); its draw, on every pass (render-only ones too),
runs the page object's transition (an animation handler started on its
first call, then run until it says done; `ScreenPages::Finish`) or else
the movie (`UiMovie::Run(movie, 0)`). The screens' answers to the
machine come from their last page (the pause menu's page 5, the menu
after the race's page 7, the results' page 4). Debug text calls to the
empty `sub_82106540` (`audio.md`: (100, 50 + 20i, 0, text) for a title
and the items, (90, 20 × (selection + 5), 0, `0x8200A044`) for a cursor)
are left in the pause menu's main page and the menu after the race's
draw: the retail game drops them.

- **The pause menu** (`[0x826D84D0]`, `PauseMenu::`, UI movie 4): opened
  by `PauseMenu::Open` at a kind (0 to 8: which items, up to six from
  the table at `0x8200CBF0`, six words a kind, -1 ends them; the
  machine's handlers pick it by the race kind; in the image, kinds 0
  to 8: (0, 1, 2, 3, 5), (0, 1, 2, 3, 4), (0, 1, 2, 3, 5, 6), (0, 1, 2,
  3, 7, 6), (0, 1, 2, 3, 7), (0, 2, 8, 6), (0, 1, 2, 3, 9, 6), (0, 4),
  (0, 2, 10): item 0 the resume, 1 to 3 the sub-pages, the rest end or
  restart the race after the dialog), six pages (0 the main
  list; 1 the four HUD options; 2 the effects and music volume; 3 three
  values from -10 to 10; 4 the confirm dialog; 5 closing, the answer),
  21 transitions. Its data (`[0x826D84D4]`, 160 bytes) copies the
  options from player 0's save data (+0x1F85C) at opening and writes
  them back at closing (`PauseMenu::SaveOptions`, the machine's
  `ClosePause`; the HUD then applies them, `RaceHud::ApplyOptions`).
  The answer (+140): 1 the resume, 2 to 9 the items that end or
  restart the race (`RaceHudMachine::PauseUpdate` posts them).
  `../pause-menu-fix.md` covers its input repeat, its draw and the
  sub-menus' arrow.
- **The confirm dialog** (`[0x826D84F4]`, `RaceDialog::`, UI movie 14):
  a yes or no question (strings 1954 to 1959 by its mode) the pause
  menu and the menu after the race open before an item that ends the
  race, and the replay save's steps (the save device, the slot list,
  the overwrite and the errors; strings 69 to 82 and 98) over the save
  layer (`save-interface.md`). Its page 5 answers 1 (yes) or 2 (no).
- **The career's results** (`[0x826D8500]`, `CareerResults::`, 212
  bytes, UI movie 6): the prize money's tally after a career race (the
  machine's `AwardPrize` block copied in), shown by pages and
  animations; its page 4 answers 1 (`sub_825C8390`, the shared
  "returns 1", `vehicle-accessors.md`).
- **The menu after the race** (`[0x826D8510]`, `AfterRaceMenu::`, UI
  movie 9): up to four items by its kind (the table at `0x82010428`,
  four words a kind; in the image, kinds 0 to 6: (0, 1, 2), (3, 1, 2),
  (4, 1, 2), (7, 1, 2), (5, 4), (5, 1, 2, 6), (5, 1, 8): 1 the replay,
  2 its save, the others an answer, some after the dialog), the
  replay's save (the replay list
  `[0x828161F0]` + 12, `Replays::`), eight pages and ten transitions.
- **Never seen in play**, only their makers and teardowns mapped here:
  `[0x826D84E0]` (the holder's +1016, kind 4's pause menu, probably the
  split screen's, `8220FD48`-`82211590`), `[0x82814E18]` (+1028, the

What's already overridden for the pause menu (keep it in a migration):
`MenuList::Update`, `ScreenPages::Go` and `PauseMenu::ShowVolume` are
Wrapped for logging only (`--log_pause_menu`,
`src/debug/pause_menu_log.cpp`; `--log_pause_movie`,
`src/debug/pause_movie_log.cpp`), and `MenuList::GetPreviousSelection`
is XACT's native getter (one load, `src/xact/xact.cpp`). Since the
migration (B7 loop, 2026-10-31; `src/race_screens/`, adapters
`src/hooks/race_screens.cpp`, `--native_race_screens`, harness
`race_screens`), the logging overrides keep their lines and run the
native steps (the originals with the flag off). The second migration
(B7 loop, 2026-10-31) made the screens' transitions and node helpers
native (`src/race_screens/transitions.cpp` and the files beside it): their
UI movie calls go through the calls' overrides (`Play`, `PlayNamed`,
`Loop`, `Finish`, `FinishNamed` and `SetNodeText` keep their
`--log_pause_movie` lines there; `Run` its frame pacing), the node lookups
are their plain C++, and `SetText`'s unset r7 to r10 pass 0 (the user's
call, 2026-10-30). Its harness cases run in a UI movie world built as the
UI movies' own harnesses build one (`race_screens`, "the screens'
transitions and node helpers"). The third migration (B7 loop,
2026-10-31) made the confirm dialog's question page, transitions and
draw native (`src/race_screens/dialog.cpp`); the question's
`SaveSlots::RequestDevice` goes through its override, and its harness
cases point the save system's interface and the replay list at a world
of their own, so the game's save objects aren't touched. It also made
the screens' draws (`src/race_screens/draws.cpp`: the pause menu's, the
menu after the race's and the career results', each still run on every
pass, the transitions' handlers through the function table), the
options' opening and the career results' first page and three of its
transitions (`src/race_screens/career.cpp`) native. The pause
menu's two frame-rate fixes aren't in these functions: the input repeat
counts ticks because the action mappers update once a tick
(`--input_mappers_by_tick`, `sub_8210B018` in `src/hooks/input.cpp`,
`action-mappers.md`), and the sub-menus' arrow stays put because UI
movie tracks that add are skipped on render-only passes inside
`UiMovie::Run` (`--per_tick_ui_movie_tracks`,
`src/frame_pacing/per_frame_logic.cpp`). The screens' updates run on
logic passes (the machine's Update handlers); their draws, which run
the transitions and the movies, on every pass, as the original does
(the transitions' movie calls through `UiMovie::Run`, so the tracks'
fix covers them). A native version keeps both: the pages' input once a
tick, the draws every pass.

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
