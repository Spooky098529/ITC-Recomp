# Known functions: the AI drivers

The AI drivers (`AiDriver::`, `8213AAA8`-`821469D0` and `82138D00`-`8213FCF8`,
with `sub_8215F678`): the computer racers' driving. A table of 7 drivers of
6,160 bytes at `[0x826C6074]` (one per racer, by the racer's index, the
racer's word +20 in the race's list at `[0x826D82F4]` + 2308; made and
freed by the race's set-up and teardown), each tied to its vehicle
(+160). Once a tick, the race's code has each driver fill its car's
input record (`AiDriver::DriveCar`: throttle, brake and steering as
signed halfwords out of 32,767) from a path it keeps along the course's
route (`AiPath::`, the driver's +512, in `track-route.md`'s terms: route
positions, sections, slices, lanes and branch masks): a ring of up to 80
entries ahead, one a slice, each with a line across the road (an offset
from the slice's center), shaped by the corners listed on the route's
slices (`AiCorner::`, up to 8 records), the road's room, and the other
racers (`AiOther::`, a 40-byte record per pair, kept by
`AiDrivers::UpdateAll`). The driver steers at a point on that line
ahead, sets a target speed from the corners and its state (chasing or
holding off given racers, states 2 to 6), and eases the pedals toward
it; a skill block (`AiSkill::`, the driver's +6048, seven halfwords from
the driver's profile plus three timed triggers) tunes it and sets a
percentage written to the vehicle's +2432. The driver's speed (+100) is
in km/h. Read by the B7 loop's mapping agent, 2026-10-23, from the
course's route's lead (`track-route.md`); the race code's other users of
the route (`sub_82162330`, `sub_82163C50`, `sub_82166658`, `sub_82168B80`,
in the race states' area `8215F000`-`82169400`) aren't in this file
(`../loops/leads.md`). The names are ours, and many of the fields'
meanings are guesses (rows say so); the layouts are in
`../known-data.md` ("AI driver", "AI path", "AI corner record", "AI
other-racer record", "AI skill").

Shared with other files, without rows here: `TrackRoute::` (`track-route.md`:
`Normalize`, `NormalizeLane`, `NormalizeLaneMasked`, `NormalizePath`,
`OnSlice`, `LocateAt`, `LaneAt`, `Distance`, `ClampPosition`),
`Race::RacerCount` (`sub_821705F8`, `collision-world.md`),
`Vehicle::Get`, `Vehicle::Identity`, `Vehicle::GetSpeedKmh`,
`RigidBody::AngularVelocity`, `sub_820B6928`, `sub_820C0450`
(`vehicle-accessors.md`), the math functions (`atan2`, `sin`, `cos`,
`memcpy`, `memset`: `c-runtime.md`) and operator new and delete
(`heap.md`). Not mapped: `sub_821434E8` (returns `[0x826C6078]`, in the
data tables' lead) and `sub_820900C0` (the array destructor iterator, in
its own lead), which `AiPath::NoteFixedSections` and
`AiDrivers::DestroyRings` call.

Not seen in play, so without rows: `sub_8213D3D8` (a jump target in
`AiPath::BranchMasksFor` the recompiler made a function of), the
tail-call targets `sub_82139A08`, `sub_8213AB40` and `sub_821462A0`
(from `AiDriver::UpdateSteerInput` and `UpdateState`), `sub_8213BDF0`
and `sub_8213BE80` (`AiPath::JoinCornerPair`'s other cases),
`sub_8213D898` (`AiPath::AvoidOthers`' flag 0x10), `sub_8213F7E0` and
`sub_8213F868` (two of the skill triggers' conditions).

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
