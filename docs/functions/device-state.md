# Known functions: the graphics device's state setters

The graphics library's (the 360's Direct3D, linked into the game) state
setters as seen in play: the render states and sampler states, each a
small function the device keeps in a table (render state `n` at device
+56 + `n`, sampler state at +440 + `n`, called by the command replay's
SetRenderState and SetSamplerState, `Command::*` 1 and 2 in
`functions.md`; their getters at +520 + `n` and +904 + `n` aren't seen
in play but one), the render target and depth surface, the viewport and
scissor, the stream sources, index buffer and textures, the blend
controls and shader constants, the device's default state at boot, and
the GPU register split with the packets it writes. Each setter writes the
device's register shadow and marks what it wrote in the dirty masks
(device +0 and +8 the vertex and pixel float constants, +16 the shader
state, +24 the render state, +32 the other state; the units by bit are in
`../gpu-functions.md`, "The register shadow as a whole"), which the
draws flush; the render states' and sampler states' names and the uses
counted in play are in `../gpu-functions.md` ("Render states and sampler
states"), the shadow's layout in `../known-data.md`. Mapped by the B7
loop (`../loops/b7-loop.md`) from its leads in `../loops/leads.md` (the
graphics device's state setters beside the resources, and
`sub_822A8A60`), 2026-10-24.

**The tables.** The setters have no direct callers: `Device::SetDefaultState`
(`sub_822ACB90`, once at boot from `Device::Init`) fills both tables from
the image's (render states at `0x826388F8`, 96 entries of 12 bytes: the
getter, the setter, the default value; sampler states at `0x82638D78`, 20
entries, run for each of 26 samplers) and calls every setter with its
default, which is why all of them ran in play; after boot, only the
states in `../gpu-functions.md`'s table are set again (the command
replay's log through the menus and a race), the rest stay at their
defaults. The states are byte offsets in the 360 SDK's order
(`D3DRS_*` and `D3DSAMP_*`; the names here are from that order and match
the registers each setter writes, so "probably" where the register alone
doesn't say). States 0-36 have no setter (`sub_82106540`, empty,
`audio.md`). A native SetRenderState or SetSamplerState would dispatch by
the state to the native setters rather than through the guest tables.

Graphics: what our Vulkan renderer needs stays native, the rest is
Dropped (the user's rule). The rows say which kind each looks like; none
is decided here. Kept-kind: every write to the register shadow, the
dirty masks and the fetch constants (the renderer reads the shadow's
seven register blocks, `0x2000`, `0x2100`, `0x2180`, `0x2200`, `0x2280`,
`0x2300` and `0x2380`, and the fetch, bool and loop constants by the
dirty masks, `ReadRegisters` in `src/native/state.cpp`, and the float
constants at device +1792 and +5888, `state.h`), the bound objects (render
targets +12184, depth surface +12200, index buffer +12180, streams
+12204, textures +12288, read by the renderer or the library's draw), the
scissor (+11600 and the rectangle at +12416, which the renderer reads in
place of the window scissor registers, `state.h`), the predicated tiling
bit (device +10808 bit 1, `0x2`, set by `SetRenderTarget` and
`SetDepthStencilSurface`; the renderer's indexed draw reads it,
`src/native/draw_packets.cpp`), the present interval (+13240, read by
`sub_822A0718`, `functions.md`) and the software copies the setters
build registers from (+11592 to +11784). Their fences (a replaced
resource's +8 set to the command position +10780, or queued on the list
at +13168) are kept with them: cheap, and the recompiled library still
reads fences (the vertex shader patch, `sub_822AE340`). Dropped-kind,
probably: the packets written straight into the command buffer (device
+40), which nothing reads since the emulated GPU went (the kick only looks
for fences and interrupts, `src/native/gpu_link.cpp`; "The indexed draw
without its packets" in `../native-renderer.md`): the screen scissor
(`Device::SetScreenScissor`), the binning and WAIT_UNTIL packets
(`Device::DirtyAllState`, `sub_8229B7D8`), the GPU register split
(`Device::SetShaderGprAllocation`, its only state +10792 read by nothing)
with its dummy draws (`sub_8229F680`), and the display's gamma ramp
packets (`sub_822B0C38`); the earlier call (2026-10-24,
`graphics-resources.md`) dropped the resource locks' cache flush packets
and fence waits the same way. With their packets left out, the setters
no longer reach the command buffer's functions (`sub_8229EF48`,
`sub_8229E308` and the segment code, a lead).

Callers in other files: the command replay's handlers (`Command::*` 1-4,
7, 11, 12, 15, 23, 24, 29-31, 34, 35, `sub_8258F5C0` and `sub_8258F0F0` (no row, probably the single commands' constants),

`sub_822A3AA8`.

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
