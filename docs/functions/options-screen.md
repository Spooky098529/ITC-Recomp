# Known functions: the options screen

The front end's **options screen** (UI movie 7, asset 22553) and the
settings it edits, read from and written back to the save data in memory.
Every front-end mode that has one builds its state machine with the same
handlers: types 6 and 7 (`Type6Options::Init` `sub_821CB6E8` and
`Type7Options::Init` `sub_821CB090`, with the second player's controller
pages `ControllerOptions`, in [`type6-type7-modes.md`](type6-type7-modes.md)),
type 2 (`Type2Options::Init`), type 4 (`Type4Options::Init`) and type 8
(`Type8Options::Init`, never made in play); their transitions and message
ids are in the Inits' rows below. The screen's
`OnEnter` allocates seven blocks (`[0x826D8470]` to `[0x826D8488]`,
`../known-data.md`), among them the 716-byte settings `[0x826D8478]`
(`o` in the rows), reset by `Settings::Reset`. `Show` reads the settings
from player 0's save data (`Settings::Read`), sets up the movie and opens
the controller pages; then each pass `Draw` runs the page shown and
`Update` the step running, both from tables of member functions built on
their frames and indexed by the options' page block `p` = `[0x826D8470]`
(+0 the page, +4 the page after the step, +8 the page before, +12 the
step, +16 the queued step, +24 the step's started word: the layout of the
controller pages' `[0x826D848C]`). `m` in the rows is UI movie 7
(`UiMovies::Find` on `0x826C5CCC`); "the menu" is `[0x826D8474]` (the
front-end menu layout, `menu-helpers.md`).

Pages (`Options::Draw`'s table): 0 the categories (page 0's menu, its
items from the category table `0x8200A578`, 5 contexts × 7 words, the
context `o` +4 from the mode's type), 1 the HUD (category 0: four on/off
values), 2 the sound (category 1: the music and effects volumes, which
`SoundOptions::SetMusicVolume` and `SetEffectsVolume` in
[`menu-sounds.md`](menu-sounds.md) apply, and a music track to preview
when unlocked), 3 the sliders (category 2: three values -10 to 10), 5 the
buttons (category 3: twelve actions' buttons), 7 the analog inputs
(category 4: six), 4, 6 and 8 the same three for context 4 (type 8,
probably split screen: both players' at once, player 1's through
`ControllerOptions`), 9 and 10 categories 5 and 6 (the save side: their
sub-pages and dialog steps are in the save screens' lead,
`../loops/leads.md`), 11 to 13 the music preview (from the sound page),
14 the close. Steps (`Options::Update`'s table, 49): 0 a wait, 1 and 2 the
buttons and analog pages' leave, 3 the fade in, 4 and 5 the categories'
animations, 6 the categories' cursor, 7 `Options::OpenCategory`, 8 the
fade out; then four a category page (enter, move, change, close): page 1
9 to 12, page 2 13 to 16, page 3 17 to 20, page 4 21 to 24, page 5 25 to
28, page 6 29 to 32, page 7 33 to 36, page 8 37 to 40; 41 to 48 pages 9
and 10's closes and dialogs (41 `sub_821C6468`, 42 `sub_821C6550`, 43
`sub_821C6638` and 46 `sub_821C69D0` in the save screens' lead; 44, 45,
47, 48 here). Every category page's last row is OK (apply the edits and
close) or Default (the defaults into the edits), its choice at `o` +660.
The settings' blocks: a 192-byte block three times, current at +44, the
edits at +236, the defaults at +428 (`../known-data.md`). Several
helpers are the same code as the pause menu's (`PauseMenu::` in
[`race-screens.md`](race-screens.md)); `Options::ShowVolumeBar`
`sub_821BE5A8` and `Options::ShowSliderMark` `sub_821BEA48` are called by
both. Shared with other files and named only here: the UI movie calls
([`ui-movies-game.md`](ui-movies-game.md), [`ui-movies.md`](ui-movies.md)),
`Menu::Step` and `Menu::Pressed` ([`menu-helpers.md`](menu-helpers.md)),
`MenuSound::Play` and `Sound::Play` ([`menu-sounds.md`](menu-sounds.md)),
`Music::Play` ([`mode-tick.md`](mode-tick.md)), `SaveData::Of`
([`vehicle-accessors.md`](vehicle-accessors.md)), `PlayTime::Mark`
([`career.md`](career.md)), `StateMachine::Add`
([`game-modes.md`](game-modes.md)), `memcpy` and `memset`
([`c-runtime.md`](c-runtime.md)), `VirtualAlloc` and `VirtualFree`
([`heap.md`](heap.md)). Names are ours and mostly guesses (the string
table wasn't read). Mapped by the B7 loop's mapping agent, 2026-11-08,
from two leads (the options screen's handlers; the options screens and
the settings' load); its reading split among three subagents, one at a
time.

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
