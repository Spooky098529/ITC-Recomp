# Known functions: the post effects

The screen-space effects drawn over each view after the scene (the code
at `82133070`-`82138C38`, with the glare's set-up at `8212EA98`-`8212EDE0`
at the end of the race overlays' range). Up to 15 **post effects**, one
object each, are kept at `0x826C5D80` (`PostEffects::`), made from a
15-entry table at `0x826174A8` (36 bytes an entry: the kind, two sort
keys, the size and position, flags and the camera pass, copied into the
object at +4; `../known-data.md`) by `PostEffects::Create`. Six kinds,
each a class with its own vtable (slot 0 records its draw, slot 1 is the
deleting destructor): kind 0 the **glow** (the bloom and star streaks;
`Glow::`, 8,480 bytes), kind 1 (8,112 bytes, never made in play), kind 2
probably a **color filter** (`ColorFilter::`, 8,128 bytes), kind 3 the
**motion blur** (`MotionBlur::`, 8,224 bytes), kind 4 (8,068 bytes, never
made in play), kind 5 a **two-pass filter over a camera pass's render
target** (`TargetFilter::`, 8,068 bytes). A race makes effects 1-3 (glow,
color filter, motion blur over camera pass 0), or 5-7 and 9-11 (the two
players' in split screen) (`sub_8215D100`, a lead); the boot makes effect
14 (a target filter over render target 3, `PostEffects::InitBoot`), which
stays past the race (flags bit 2); the race's end destroys the rest
(`PostEffects::DestroyRace`). Each draw step records the effects whose
camera pass is active (`PostEffects::RecordAll`, from `Race::DrawStep`):
each into its own chunk of the scene's command list (`[0x826BABA0]`,
`cameras.md`), handed on with its sort key: the frame (or the render
target) resolved into a texture, screen quads (rect lists of three
40-byte vertices, from two 100-vertex buffers in the object, +56 to
+8055, flipped each draw) drawn with shared shader pairs (`sub_825896D8`,
`sub_82589700`, `models.md`), the results resolved into textures. The
textures come from a pool of 20 render textures at `0x826C5DC8`, shared
by id between the effects that ask for the same one (`RenderTextures::`).

The glow's set-up fills a glare definition at +8064 from two tables
(`0x82617280`, eight of 44 bytes; `0x826171D8`, six of 28 bytes) whose
layouts are, probably, the DirectX SDK's HDR sample's glare library
(`GLAREDEF`: glare, bloom, ghost luminance, ghost distortion, star
luminance, star type, star inclination, chromatic aberration luminance,
the afterimage's sensitivity, ratio and luminance; `STARDEF`: line count,
passes, sample length, attenuation, inclination, rotation), with its
eight chromatic aberration colors. Every glow takes glare type 4 (star
type 2: four lines, two passes). The race's update sets the glows'
parameters by the car's speed (probably; `Glow::SetFromSpeed`, through
vtable slot 24) and marks every effect updated (+48, read by the glow's
history and the motion blur's matrices).

Frame interpolation hooks two of them: `Glow::Record`
(`src/interpolation/glow.cpp`: the glow's strength and history weight
blended between ticks, the history written every frame) and the motion
blur's previous view-projection copy (return `8213653C`,
`src/interpolation/blend_state.cpp`); `PostEffects::RecordAll` is
rewritten in `src/debug/frame_state_diff.cpp` for the diagnostics. How
the effects reach our renderer: "Motion blur reads the 30 Hz tick" in
`../native-renderer.md`, and "The bloom" under its known issues.

Graphics: what our Vulkan renderer needs stays native, the rest is
Dropped (the user's rule). Everything here records render commands our
renderer replays (the effects are drawn), or makes the textures and
surfaces those commands use: kept-kind. None is decided here.

`sub_8215B690` and `sub_8212EDE0` (in the lead with the glare's set-up)
are the race's toggle over these and other objects: it toggles every
effect's +44 (no glow history), the race's screen objects' +25 (the
objects `sub_82133000` makes, `../loops/leads.md`), a course scenery
flag and a scene word; probably the pause, not checked.

Mapped by the B7 loop (`../loops/b7-loop.md`) from its lead in
`../loops/leads.md` (the glare's set-up at the end of the race overlays'
range), 2026-10-24. `Glow::Record`, `MotionBlur::Record` (earlier
`View::UploadPreviousViewProjection`) and `PostEffects::RecordAll` moved
here from `functions.md`.

Status:

- **Native**: plain C++ in `itc_recomp/src/` that doesn't use the
  PowerPC context (`ctx`): normal arguments and host structs (it may
  still read and write guest memory through `src/guest.h` while
  recompiled code shares the data). The game reaches it without `ctx`,
  from native or overridden callers, and the recompiled original is no
  longer called (except behind a fallback flag or to check against it).
  No `REX_FUNC` override of it exists, not even an adapter kept only for
  a harness (that's Overridden until the adapter goes).
  The end state for every function.
- **Overridden**: an `extern "C" REX_FUNC(sub_XXXXXXXX)` override in
  `itc_recomp/src/` (or a macro defining one) does the work instead of
  the original: a thin adapter in front of native code, or a body that
  still uses `ctx` (calling guest code, reading registers). It may call
  the original when its flag is off, or to check itself against it.
- **Wrapped**: an override that does something of its own (skipping
  render-only passes, logging, timing) and still calls the original
  (`__imp__sub_XXXXXXXX`) for the work.
- **Dropped**: its work isn't needed on PC (hardware set-up, kernel calls
  the SDK already stubbed), so it no longer runs: an override in
  `itc_recomp/src/` replaces it with nothing (or a fixed return value), or
  its callers, made native, leave the call out (no override then; the row
  says which caller). Logs, a harness or the renderer's frame dumps have
  shown that nothing reads what it did. The original is no longer called,
  except behind a fallback flag while the drop is being checked. A
  function the game never calls in the first place isn't Dropped: its
  status stays blank and its row says it's never called.
- **Merged**: its work is done inside a native caller's plain C++ (a
  few lines only that caller needs), so it has no function or override of
  its own in `itc_recomp/src/`. The row names the caller(s) and the
  harness that covers the work. The original is no longer called, except
  behind the caller's fallback flag.
- **Patched**: the generated code was edited in place (search for
  `PATCH:`).

A function usually moves from recompiled or Wrapped to Overridden to
Native as the `ctx` edge moves up through its callers, or straight to
Dropped when its work isn't needed.
`itc_recomp/tools/check_function_statuses.py` checks this column, in
every file of the tables, against `src/` (an override marked Native, a
status with no override, an override with no row, a row in two files);
run it after changing either, on any branch.
