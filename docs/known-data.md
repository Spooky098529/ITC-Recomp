# Known data

The game's globals and object fields worked out so far (the functions
are in [`functions/`](functions/functions.md)).

| Address | What | Notes |
|---|---|---|
| vehicle+0x30 | Speed (float, m/s) | Read by `Vehicle::GetSpeedKmh`. |
| vehicle+0xD0 | Vehicle world matrix | 4x4 row-major: rotation rows, then position row (w = 1). The car's forward axis is -row 0. |
| vehicle+0xCF0 | Copy of the world matrix | Identical every tick; not yet known which one drawing reads. |
| `0x826BAC10` | Camera view matrix | Pass 0's view (+0x10). The camera position is -t·Rᵀ. In the car's frame the views sit at (-5.48, 1.34, 0) for chase, (-0.44, 0.67, 0) for bumper and (-0.26, 0.85, -0.38) for cockpit. Writing it has no effect while driving: Draw rebuilds it from the eye and target. |
| `0x826BAC00` | Camera pass array | 21 objects of 592 bytes: view +0x10, projection +0x50, view-projection +0x90, eye +0x190, look-at target +0x1A0, up +0x1B0. Pass settings at +564 to +588, active flag at +588. Pass 0 is the main 1280x720 view; pass 10 a 1024x1024 reflection and 11 a 512x512 shadow map, both rebuilt in Draw. |
| `[0x82814E34]` | Title screen object | +4 state (5 = start the attract race), +36 idle ticks. See "The title screen" in `title-screen.md`. |
| car + 16 | The car's world matrix, for drawing | Copied in by `sub_8215C780` each tick; the cockpit dials' parent. |
| car + 696, + 700, + 704 | Speed (km/h), revs, boost | Set each tick by `sub_8215C780`; the cockpit dials read them (`sub_820E42E8`, `sub_820E45A8`). `sub_820DAC68` takes 1.0 off + 704 every pass. |
| `0x70180000` | Main thread stack | During Draw, holds temporary world matrices and camera copies passed to the recorders (for example 0x7018E640). Not render state. |
| save owner | Save slots' owner (`r3` of the `SaveSlot` steps) | +16 the content's root name, +44 the slots (1,000 bytes each), +52 the device selector's flags, +60 and +64 the save's size and a count (for `sub_82295C18`), +68 how many saves to enumerate. See `functions/files-and-saves.md`. |
| save slot | One save slot (1,000 bytes) | Overlappeds (28 bytes): +8 the device selector, +48 the enumeration, +100 the open, +136 create, delete and thumbnail, +472 the file read or write (its event at +488, also kept at +492). +36 the device (0 for none), +40 its free bytes (64-bit), +76 the enumerator, +80 its buffer (308-byte XCONTENT_DATA each), +88 its size, +164 the XCONTENT_DATA used (+168 its content type), +496 the file handle, +500 bytes done, +504 the display name (UTF-16), +760 the file name, +802 the file's path, +932 and +936 the data and its size, +940 and +944 the thumbnail and its size, +956 the user, +960 and +964 the state the steps share. See `functions/files-and-saves.md`. |
| movie source | The movie player's file data source (vtable `8204DD50`, one per stream) | +44 the handle (-1 closed), +48 the end flag, +56 the start and +64 the size (64-bit), +72 and +80 the blocks' window (start and bytes), +88 the position, +96 a read count, +104 the block size, +108 the block count, +112 the current block's index, +116 the blocks to keep ahead, +120 flags (1 opened by path, 4 the handle was the caller's, 8 loop), +124 the blocks' memory, +128 the current block, +132 the block list. Ours makes no blocks (+108, +124, +132 stay 0). See `functions/files-and-saves.md`. |
| camera pass + 0x1D0 | Probably the view direction | 16 bytes; the sprite overlays (`sub_82129A08`, `sub_8212ACF0`, `sub_8212CE40`) skip what's behind the camera by the dot product of its offset from the eye (+0x190) with it, and face billboards with it (`functions/sprites.md`). |
| `0x826C5D5C`, `0x826C5D60` | The render queue and the command list the sprite recorders use | `[0x826C5D60]` is the list `sub_8258C9D0`, `sub_8258CAA0` and `sub_8258CA50` work on; `[0x826C5D5C]`'s vtable slot 4 takes a closed chunk (r4), its layer (r5, from `sub_82126630`) and depth (f1) (`sub_82128750`, `sub_821281A8`, `sub_82128E70`). |
| command list | The graphics library's command list (vtable `0x8206C080`; the scene's at scene + 8, `functions/command-list.md`) | +4 the buffer being recorded (0 or 1, flipped each tick), +8 each buffer's capacity in slots, +12 slots used this tick, +16 the last tick's, +20 the allocation (both buffers), +24 and +28 the two buffers, +32 where the next chunk starts, +36 and +40 the last chunk's start and end, +44 the write pointer, +48 the open chunk's start (no reader found here), byte +52 a chunk is open. |
| `0x8296B918`, `0x82970BD8` | The scene's command list (scene + 8) | Stored by the scene's constructor `sub_82098A98`; recorders read the first (`sub_825953D0`, `sub_82146BD0` and others). `0x8296B91C` and `0x82970BD4` hold scene + 64. |
| `0x8296BD28` | Open command list chunks | Up by 1 in `sub_8258C9D0`, down in `sub_8258CA50`; a debug message when a chunk opens with one already open. |
| `0x826BABA0` | Probably the scene's render manager | The light billboards (`sub_8209CC38`) reach the command list through its vtable slot 8, then that object's slot 1, and the render queue through slot 8, then slot 2. |
| sprite list | The race overlays' sprite list (0x10A00 bytes, on the overlay's stack) | +0 a 4x4 matrix (identity), +64 skip flag (drawn only when 0), +68 and +72 render state modes (0-5 and 0-3), +80 corners: 500 sprites × 4 corners × (x, y, z, w), +32080 the corners' colors (four words a corner, packed to ARGB when recorded), +64080 and +66080 two words a sprite choosing its texture coordinates (0-3, others the whole texture), +68080 (0x109F0) the count (at most 500), +68084 the texture. Reset by `sub_821298C0`, recorded by `sub_82128750`. A single sprite (`sub_8211EB60`, `sub_821281A8`) has the same layout up to its four corners at +80. |
| screen rectangle | An overlay's 2D quad (`sub_82128E70`) | +64 skip flag, +80 x, +84 y, +88 width, +92 height (integers, pixels), +96 to +108 u0, v0, u1, v1, +112 texture, +116 alpha blending. |
| trail overlay | The overlay `sub_82129A08` records (probably the light trails) | +104 ring capacity, +108 its texture holder ([+108]+0), +128 the ring of 128-byte points, +0xFA80 the head index, +0xFA88 the point count. A point: +0 position, +32 to +44 its color (four words), +48 must be nonzero, +60 sequence number, +64 direction, +80 and +96 the ribbon's edge points, +112 valid, +116 set to 1 where the trail breaks, +120 a texture coordinate word. |
| billboard material | A light group's billboard set-up (on `sub_82148658`'s stack) | +0 alpha mode (1, 16, 32, 64, 256 or 1024), +4 blend mode (1, 2, 4, 8 or 16), +12 texture, +32 light count, +36 the lights (48 bytes each: +0 position, +32 and +36 sizes). Made by `sub_8209F5A0` and `sub_8209F5C8`. |
| `0x826A509C`, `0x826A50A0`, `0x826A50A4` | Billboard vertex count and shaders | `sub_8209C6E0` adds each batch's vertex count to the first; `sub_8209C1A0` records the other two (probably the vertex and pixel shaders). |
| `0x8266B470` | `asin` and `acos`'s constants (`functions/c-runtime.md`) | Floats at +0 to +12 (the 0.5 split and the scales), doubles at +16 and +32 (the constants added: probably 0, π/2, π) and the rational polynomial's coefficients at +48 to +120. Native math must use these values as they are. |
| `0x8266B660` | `atan` and `atan2`'s constants | Doubles: +8 probably π/2, +16 probably π, +24 the reduction's bound (probably 2 - √3), +40 its factor, +48 the large-argument bound, +56 to +112 the polynomial, +128 the constants added by range; floats at +168 (0.0) and +176 (1.0). |
| `0x8266B718` | `sin` and `cos`'s constants | Doubles: +0 probably π/2, +8 probably 1/π, +16 the largest argument, +40 and +48 π in two parts, +56 to +112 the polynomial; floats at +24 to +36 (probably 0, 1.0, -1.0 and 0.5: +28 and +32 give the sign). |
| `0x8266B790`, `0x820723B8` | `tan`'s constants | `0x8266B790` +0 and +8: π/2 in two parts; `0x820723B8`: +0 probably 2/π, +8 the small-argument bound, +16 the largest argument, +48 probably 1.0, with the polynomial's coefficients at `0x82072410` to `0x82072428`. |
| `0x82072588` to `0x82072610` | `log`'s constants | The table at `0x82072588` (+0 probably √0.5, +8 ln 2's low part, +40 and +64 coefficients), coefficients at `0x820725D8` to `0x820725F8`, `0x820725E8` ln 2's high part, `0x82072600` the denormal scale, `0x82072608` the smallest normal, `0x82072610` probably the largest double; `log10` multiplies by `0x820725A0`. |
| `0x8266BC30`, `0x8266BC38` | Probably +infinity and the C runtime's default NaN | `log(0)` returns -[`0x8266BC30`], `ldexp`'s overflow takes its sign; out-of-range `sin`, `cos`, `tan` and `log` of a negative return [`0x8266BC38`] (negated for `log`). |
| `0x8266BB48`, `0x8266BC28` | The C locale's data and the current locale's pointer | +200 the character type table's pointer (halfwords: 1 upper, 2 lower, 4 digit, 8 space, 0x100 alpha, 0x8000 lead byte), read by `isalpha`, `isdigit`, `isalnum` (`0x8266BB48` directly) and `isleadbyte`, `strtoxl`, `_atof_l` (through `[0x8266BC28]`); +172 the longest multibyte character (above 1 uses `sub_825AFD98`, never seen). |
| `0x8266BA5C` | The float conversion table (`_cfltcvt_tab`) | Ten function pointers filled at start-up by `sub_825A6DB0`; `_output_l` calls through it (+24 `_cfltcvt_l`, `sub_825AEB20`). |
| `0x8266B7D0` | The C runtime's streams (`_iob`) | 32 bytes a stream (20): stdin, stdout (+32), stderr (+64); `__iob_func` returns it. A string stream on the stack has the same layout: +0 the pointer, +4 room left, +8 the base, +12 flags (66 for `sprintf`'s; 0x40 a string). |
| `0x82971170`, `0x82971178`, `0x8297132C`, `0x82971328`, `0x82978320` | C runtime handler pointers | Cleared or set once by `_init_pointers` (`sub_825AA398`) and its setters; `0x8297832C` is `setjmp`'s hook (jumped to when set). `0x82978338` is `__initmbctable`'s done flag. |
| per-thread data + 20 | `rand`'s seed | In the calling thread's C runtime data (`_getptd`, `sub_825AA580`, TLS): seed × 214013 + 2531011 each call. |
